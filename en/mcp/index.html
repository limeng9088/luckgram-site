Luckgram / MCP

Luckgram MCP

Luckgram Desktop has an MCP server built in. Your AI tool lists the Telegram accounts on your computer, switches between them, and uses the skills you allow for each account.

  • Off by defaultThe server, the cloud and every skill of every account are switched on by you.
  • Local firstListens on 127.0.0.1 only. The cloud is optional.
  • Limits built inEverything that changes an account is rate limited per account.

Quick start

  1. Install Luckgram Desktop for Windows and sign in to your accounts.
  2. Open Settings → Luckgram → Local MCP server and switch it on.
  3. Click the row and use Copy client config or Copy access token.
  4. Connect your AI tool (next section) and ask it: “Which Telegram accounts am I logged in to?”

Connect your AI tool

<TOKEN> is the access token from the settings page. For the cloud, use https://mcp.luckgram.cc/mcp as the address and the cloud key as the token; everything else is the same.

Claude Code

claude mcp add --transport http luckgram http://127.0.0.1:28765/mcp \
  --header "Authorization: Bearer <TOKEN>"

Check with claude mcp list: the line for luckgram ends with Connected.

Kiro

Put this in .kiro/settings/mcp.json in your project, or in ~/.kiro/settings/mcp.json for every project:

{
  "mcpServers": {
    "luckgram": {
      "url": "http://127.0.0.1:28765/mcp",
      "headers": { "Authorization": "Bearer <TOKEN>" }
    }
  }
}

Then ask Kiro to call list_accounts.

Codex

Codex reads the token from an environment variable, so it is not written into its config file:

export LUCKGRAM_MCP_TOKEN="<TOKEN>"
codex mcp add luckgram --url http://127.0.0.1:28765/mcp \
  --bearer-token-env-var LUCKGRAM_MCP_TOKEN

On Windows set the variable with setx LUCKGRAM_MCP_TOKEN "<TOKEN>" and open a new terminal. The command writes this to ~/.codex/config.toml:

[mcp_servers.luckgram]
url = "http://127.0.0.1:28765/mcp"
bearer_token_env_var = "LUCKGRAM_MCP_TOKEN"

opencode

opencode mcp add luckgram --url http://127.0.0.1:28765/mcp \
  --header "Authorization=Bearer <TOKEN>"

The header is written as name=value. Check with opencode mcp list: it shows connected. Right after adding it may still say pending; run it again a few seconds later.

Other tools

Any MCP client that speaks HTTP works. Most accept this JSON:

{
  "mcpServers": {
    "luckgram": {
      "type": "http",
      "url": "http://127.0.0.1:28765/mcp",
      "headers": { "Authorization": "Bearer <TOKEN>" }
    }
  }
}

Tested with Claude Code 2.1, Kiro CLI 2.31, Codex CLI 0.144 and opencode 2.0, against the local and the cloud address.

Cloud: all your computers at one address

The local server works on one computer. With the cloud on, Luckgram Desktop connects out to mcp.luckgram.cc, so your AI tool reaches it from anywhere and several computers share one address. No public IP, no port forwarding.

  1. On the first computer: the same settings page → switch on Connect through the cloud. A cloud key is made on your computer.
  2. Click Copy cloud client config and paste it into your AI tool: 
    {
  "mcpServers": {
    "luckgram-cloud": {
      "type": "http",
      "url": "https://mcp.luckgram.cc/mcp",
      "headers": { "Authorization": "Bearer lgc_..." }
    }
  }
}
  3. On every other computer: Use the cloud key of another computer, paste the key, then switch on Connect through the cloud.
  • The tools are the same, each with one more argument, device. list_devices shows your computers and which are online.
  • Skills stay per account and are switched on in the app on each computer. Rate limits are counted on each computer too.
  • list_recent_calls shows the last 200 calls that went through the cloud: time, tool, computer, account, failed or not.
  • If luckgram.cc does not open on your network, use the backup address https://lg-mcp.cat158.com/mcp. It is the same service with the same computers, and Luckgram Desktop switches to it by itself.

Calling it directly

The server speaks MCP over HTTP: one POST per JSON-RPC message, a JSON answer. No session, no stream. A tool call looks like this:

POST /mcp
Authorization: Bearer <TOKEN>
Content-Type: application/json

{"jsonrpc":"2.0","id":1,"method":"tools/call",
 "params":{"name":"list_chats","arguments":{"account":"7943234085","unread_only":true}}}

The answer has the result twice: as text in content and as JSON in structuredContent. A tool that could not do what was asked answers with isError: true and says why in plain words.

From another computer without the cloud, forward the port over SSH:

ssh -N -L 28765:127.0.0.1:28765 user@computer-with-luckgram

Security

  • The local server listens on 127.0.0.1 only. It cannot be reached from your network or the internet.
  • Every request needs the access token. It is generated on your computer, kept in the system credential store, and can be regenerated at any time.
  • Requests from web pages are refused, so a site you visit cannot call it through your browser.
  • The cloud only passes requests on. It does not store arguments, results or chats, and it does not store the cloud key itself.
  • Whoever has the access token or the cloud key can use what you switched on. If one leaks, regenerate it: the old one stops working at once.
  • What a skill returns goes to your AI tool and its model. Switch on reading messages only for accounts whose chats you are willing to share with it.

Troubleshooting

What you seeWhat to do
The tool cannot connectLuckgram Desktop has to be open, with Local MCP server switched on. The page shows the address in use: when port 28765 is taken, the next free one is used.
401, “Missing or wrong access token”The token in your tool is not the current one. Copy it again; after Regenerate access token the old one stops working.
“The … skill is off for account …”That skill is not switched on for that account. Switch it on in the same settings page, under the account's name.
“Rate limit … Try again in N seconds”The per-account limit of that tool was reached. Wait the stated time. The limits cannot be switched off.
“Luckgram Desktop is locked with a passcode”Unlock the app on the computer. While it is locked nothing is listed and nothing runs.
The cloud says no computer is onlineOpen Luckgram Desktop on that computer and check that Connect through the cloud is on and says “Connected”. Where luckgram.cc is blocked the app switches to the backup address by itself; your AI tool needs the backup address too.
