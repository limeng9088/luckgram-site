# luckgram.cc

Static website for Luckgram, served by GitHub Pages behind Cloudflare.

Pages are generated by `scripts/build.py`; edit the content there, then run
`python3 scripts/build.py` and commit the output.

## MCP and the Skill market

`/mcp/` documents the MCP server built into Luckgram Desktop; `/skills/` is the Skill market,
with one page per skill at `/skills/<key>/`. The texts of the skills (name, logo, what it
does, example requests, tools, limits) are in `scripts/skills_data.py`, one entry per skill;
the pages are written by `mcp()`, `skills()` and `skill_page()` in `build.py`. Keep them in
step with `docs/local-mcp.md` in luckgram-desktop: tools, arguments and limits are what the
app does. A new skill is one entry in `SKILLS` (its `icon` is the inside of a 24×24 SVG,
its `hue` the colour of its logo), then the translations as for any other text.

`/skills/luckgram/luckgram-skill.zip` and `SKILL.md` are the `luckgram` skill for agents,
copied from `skills/luckgram` in cicy-skills.

## Languages

| | Path | Written in |
|---|---|---|
| 简体中文 | `/` | `scripts/build.py`, `data/features.json` |
| English | `/en/` | `scripts/build.py`, `data/features.json` |
| 繁體中文, Русский, Español, Português (Brasil), العربية, فارسی, Bahasa Indonesia, Türkçe | `/zh-hant/`, `/ru/`, `/es/`, `/pt-br/`, `/ar/`, `/fa/`, `/id/`, `/tr/` | `locales/<code>.json` |

- Copy is written once, as `t("English", "中文")`. The other languages are looked up by the
  English text in `locales/<code>.json` (English text → translation). A text with no translation
  is shown in English, and the build says how many there are (`--missing` lists them,
  `--strict` fails on them).
- After changing copy: `python3 scripts/build.py --export` rewrites `locales/source.json`
  (everything there is to translate, English → Chinese); add the new texts to each
  `locales/<code>.json`, then `python3 scripts/check_locales.py` (same texts, same tags and links)
  and `python3 scripts/check_site.py` (see below).
- A new language: one line in `LANGUAGES` and `OFFER` in `build.py`, and its `locales/<code>.json`.
  A language is built only when its file is there.
- Arabic and Persian pages are `dir="rtl"`. `assets/site.css` only uses start/end
  (`padding-inline`, `inset-inline-start`, …), never left/right, so they need no rules of their own.
- The Privacy Policy and Terms of Use exist in Chinese and English only (legal text is not
  machine-translated): the other languages link to the English ones, traditional Chinese to the
  simplified ones.
- The Help Center has Chinese and English: the other languages link to its English pages.
- Nobody is redirected by language. When the browser asks for a language the page has, a bar
  offers it (script in `footer()`); `x-default` is English.
- The translations in `locales/` were machine-made and have not been reviewed by native speakers.

## Search engines and AI assistants

`build.py` also writes, and `scripts/check_site.py` checks:

- per page: `canonical`, `hreflang` for every language of the page plus `x-default`, Open Graph
  and Twitter tags (`assets/og.png`, 1200×630), and schema.org structured data (Organization,
  WebSite, WebPage, BreadcrumbList; on the home page SoftwareApplication and FAQPage; on the
  features page an ItemList)
- `sitemap.xml` (every page in every language, with its alternates) and `robots.txt`
- `llms.txt` and `llms-full.txt`: what Luckgram is, the facts, every feature and the FAQ as plain
  Markdown, from the same texts as the pages
- `MODIFIED` in `build.py` is the date given as last modified: change it when content changes.

## Feature list

`data/features.json` is the single list of Luckgram features (id, Chinese and English
name, one-line title, description, group, status, Help Center path). The features page
and the feature cards on the home page are generated from it, and wiki.luckgram.cc
copies the same file (`scripts/sync-features.py` in luckgram-wiki) for its feature
catalog and the status line on each feature page.

Each feature also says where it stands in the web app (web.luckgram.cc): `"web": "live"` or `"none"`,
and `web_note` for what differs there (the features page shows a line for the ones that are live).

When a feature ships or changes, edit `data/features.json`, run
`python3 scripts/build.py`, and then sync the wiki.

## Mirror domains (cat158.com)

Some networks block luckgram.cc by domain name (luckgram-specs#160). The same content is
served under cat158.com by the Worker `luckgram-mirror` (`edge/mirror-worker.js`):

| Main | Mirror |
|---|---|
| `luckgram.cc` (this site, GitHub Pages) | `lg-www.cat158.com` |
| `wiki.luckgram.cc` (Help Center, GitHub Pages) | `lg-wiki.cat158.com` |
| `dl.luckgram.cc` (downloads, `edge/dl-worker.js`) | `lg-dl.cat158.com` |

- The Worker proxies the main host on every request, so the mirrors follow the main site
  with no extra step. GitHub Pages' custom domain (`CNAME`) stays as it is.
- HTML: absolute links to the three main hosts (and `www.luckgram.cc`) and redirect
  `Location`s point at the mirrors; relative links work unchanged. `canonical` and
  `hreflang` links keep naming the main host (a canonical is added if the page has none),
  and every response has `X-Robots-Tag: noindex`.
- `web.luckgram.cc` links point at `lgweb.cat158.com`, the web app's own backup entrance
  (a second custom domain of Pages project `luckgram-web`, not proxied by this Worker).
- Downloads: bytes, `Range` (206) and SHA-256 are the main host's. On the download page the
  buttons use `lg-dl.cat158.com` when the page is opened on `lg-www.cat158.com`, or when
  `dl.luckgram.cc` doesn't answer within 6 s (script in `scripts/build.py`).
- Deploy (Cloudflare account that holds the `cat158.com` zone):
  `cd edge && npx wrangler deploy -c mirror-wrangler.toml`. No secrets or bindings.
- Tests: `node --test edge/mirror-worker.test.mjs`.
