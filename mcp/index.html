Luckgram / MCP

Luckgram MCP

Luckgram 桌面版内置 MCP 接口。你的 AI 工具可以列出电脑上的 Telegram 账号、在账号之间切换，并使用你为每个账号开启的 Skill。

  • 默认关闭接口、云端、每个账号的每个 Skill，都要你亲手打开。
  • 本机优先只监听 127.0.0.1。云端是可选的。
  • 内置上限所有会改动账号的操作都按账号限制频率。

快速开始

  1. 安装 Windows 版 Luckgram 桌面版并登录账号。
  2. 打开 设置 → Luckgram 功能 → 本机 MCP 接口，把开关打开。
  3. 点进这一行，使用复制客户端配置或复制访问令牌。
  4. 连接你的 AI 工具（见下一节），然后问它：“我登录了哪些 Telegram 账号？”

连接你的 AI 工具

<TOKEN> 是设置页里的访问令牌。接云端时，把地址换成 https://mcp.luckgram.cc/mcp、令牌换成云端密钥，其余步骤相同。

Claude Code

claude mcp add --transport http luckgram http://127.0.0.1:28765/mcp \
  --header "Authorization: Bearer <TOKEN>"

用 claude mcp list 检查：luckgram 那一行末尾显示 Connected。

Kiro

把下面的内容写到项目里的 .kiro/settings/mcp.json；想对所有项目生效，就写到 ~/.kiro/settings/mcp.json：

{
  "mcpServers": {
    "luckgram": {
      "url": "http://127.0.0.1:28765/mcp",
      "headers": { "Authorization": "Bearer <TOKEN>" }
    }
  }
}

然后让 Kiro 调用 list_accounts 试一下。

Codex

Codex 从环境变量读取令牌，令牌不会写进它的配置文件：

export LUCKGRAM_MCP_TOKEN="<TOKEN>"
codex mcp add luckgram --url http://127.0.0.1:28765/mcp \
  --bearer-token-env-var LUCKGRAM_MCP_TOKEN

Windows 上用 setx LUCKGRAM_MCP_TOKEN "<TOKEN>" 设置变量，然后重新打开终端。上面的命令会在 ~/.codex/config.toml 里写入：

[mcp_servers.luckgram]
url = "http://127.0.0.1:28765/mcp"
bearer_token_env_var = "LUCKGRAM_MCP_TOKEN"

opencode

opencode mcp add luckgram --url http://127.0.0.1:28765/mcp \
  --header "Authorization=Bearer <TOKEN>"

请求头的写法是 名称=值。用 opencode mcp list 检查，显示 connected 即可。刚添加完可能还显示 pending，过几秒再运行一次。

其他工具

任何支持 HTTP 传输的 MCP 客户端都能用。大多数接受下面这段 JSON：

{
  "mcpServers": {
    "luckgram": {
      "type": "http",
      "url": "http://127.0.0.1:28765/mcp",
      "headers": { "Authorization": "Bearer <TOKEN>" }
    }
  }
}

已在 Claude Code 2.1、Kiro CLI 2.31、Codex CLI 0.144、opencode 2.0 上用本机地址和云端地址测试。

Skill

工具能做什么，是按账号决定的。在你为某个账号开启 Skill 之前，工具只能列出账号和切换账号。每个 Skill 在 Skill 市场里都有自己的页面。

账号查看所有已登录的账号，在账号之间切换。始终开启好友查看账号的好友，按用户名或手机号查找用户。只读管理好友加好友、删好友。不会发送任何消息。会改动账号会话查看会话列表和未读数，不含消息内容。只读管理会话把会话标记为已读。会改动账号读消息读取会话里的消息，不会标记已读。只读发消息发送文字消息，一次只发给一个会话。会改动账号群组和频道加入公开的群组和频道，或者退出。会改动账号资料修改账号的昵称和简介。会改动账号BotFather 机器人管理通过 @BotFather 创建和管理你的 Telegram 机器人。会改动账号

云端：一个地址管理所有电脑

本机接口只能在一台电脑上用。打开云端后，桌面版会主动连到 mcp.luckgram.cc，AI 工具从任何地方都能连上，多台电脑共用一个地址。不需要公网 IP，也不需要端口转发。

  1. 在第一台电脑上：同一个设置页 → 打开通过云端连接。云端密钥在你的电脑上生成。
  2. 点复制云端客户端配置，粘贴到 AI 工具里： 
    {
  "mcpServers": {
    "luckgram-cloud": {
      "type": "http",
      "url": "https://mcp.luckgram.cc/mcp",
      "headers": { "Authorization": "Bearer lgc_..." }
    }
  }
}
  3. 在其他每台电脑上：点使用另一台电脑的云端密钥，粘贴密钥，再打开通过云端连接。
  • 工具和本机版相同，每个工具多一个 device 参数。list_devices 列出你的电脑和在线状态。
  • Skill 仍然按账号开启，在每台电脑各自的应用里设置。频率上限也在每台电脑上各自计数。
  • list_recent_calls 可以查看最近 200 次经过云端的调用：时间、工具、电脑、账号、是否失败。
  • 如果你的网络打不开 luckgram.cc，把地址换成备用地址 https://lg-mcp.cat158.com/mcp。它是同一个服务、同一批电脑，桌面版会自己切换过去。

直接调用

接口使用 MCP 的 HTTP 传输：每条 JSON-RPC 消息一个 POST，返回 JSON。没有会话，也没有流。一次工具调用是这样的：

POST /mcp
Authorization: Bearer <TOKEN>
Content-Type: application/json

{"jsonrpc":"2.0","id":1,"method":"tools/call",
 "params":{"name":"list_chats","arguments":{"account":"7943234085","unread_only":true}}}

返回里结果有两份：content 里的文字和 structuredContent 里的 JSON。工具没能完成时返回 isError: true，并用一句话说明原因。

不用云端、从另一台电脑调用时，用 SSH 转发端口：

ssh -N -L 28765:127.0.0.1:28765 user@computer-with-luckgram

安全

  • 本机接口只监听 127.0.0.1，局域网和外网都连不上。
  • 每个请求都要带访问令牌。令牌在你的电脑上生成，保存在系统凭据库里，随时可以重新生成。
  • 来自网页的请求会被拒绝，你访问的网站无法借浏览器调用它。
  • 云端只转发请求：不保存参数和结果，不保存聊天内容，也不保存云端密钥本身。
  • 拿到访问令牌或云端密钥的人，可以使用你已开启的功能。泄露后请立即重新生成，旧的立刻失效。
  • Skill 返回的内容会交给你的 AI 工具和它背后的模型。只给你愿意让它看聊天内容的账号开启读消息。

排查问题

现象怎么办
工具连不上Luckgram 桌面版要开着，并且打开了本机 MCP 接口。设置页会显示实际使用的地址：28765 端口被占用时会顺延到下一个空闲端口。
401，“Missing or wrong access token”工具里的令牌不是当前的令牌。重新复制一次；点过重新生成访问令牌后旧令牌就失效了。
“The … skill is off for account …”这个账号没有开启这个 Skill。在同一个设置页里，到该账号名下把它打开。
“Rate limit … Try again in N seconds”这个工具在该账号上达到了频率上限。等待提示的时间即可。上限不能关闭。
“Luckgram Desktop is locked with a passcode”到电脑上解锁应用。锁定期间不列出任何账号，也不执行任何操作。
云端提示没有电脑在线在那台电脑上打开 Luckgram 桌面版，确认通过云端连接已打开并显示“已连接”。luckgram.cc 被屏蔽的网络里应用会自己切到备用地址，AI 工具那边也要换成备用地址。
